# AutoTramita.es — DNS, Nextcloud and mail
Status: Accepted design decisions and initial infrastructure implementation, 2026-11-24.

## Infrastructure inventory — 2026-11-24

- Cloudflare zone `autotramita.es` is active and delegated to `darl.ns.cloudflare.com` and `elinore.ns.cloudflare.com`. The Traefik Cloudflare DNS token can manage its DNS records.
- Cloudflare DNSSEC is disabled; no DS record was returned by DNS. Enabling DNSSEC requires coordinating the registrar DS record and verifying the chain.
- The existing shared `traefik` container listens on ports 80 and 443, uses the external Docker network `proxy`, disables automatic Docker service exposure, and has a Cloudflare DNS-01 certificate resolver. It already serves other production stacks. Its watched dynamic configuration was extended for DEV without restarting the container.
- The user chose the existing shared Traefik for both environments, replacing the earlier decision to run one Traefik per environment. Separate PROD and DEV Compose projects and application networks are prepared but not yet deployed; the shared proxy is a common infrastructure trust boundary, not complete network isolation. Both tunnel connectors run, but nested DEV traffic now goes directly to Traefik rather than through its tunnel.
- Created remotely managed tunnels `autotramita-prod` (`5f95fa5c-8748-45b8-9404-de3b04869889`) and `autotramita-dev` (`ce079324-ac38-4a71-8acc-7760d4cb378d`). Their Docker connectors are defined in `docker-compose.tunnels.yml`, joined to the existing `proxy` network and reported healthy by Cloudflare. Manage with `docker compose -f docker-compose.tunnels.yml up -d`; credentials are in root-only ignored `.secrets/cloudflared-{prod,dev}.env` files and must be backed up securely.
- The PROD tunnel routes `autotramita.es` and `www.autotramita.es` to the shared Traefik over HTTPS with origin certificate verification; other hostnames fall through to `http_status:404`. The DEV tunnel currently has only a 404 catch-all. No AutoTramita application backend is deployed; the separately configured DEV fallback and shared Nextcloud routers are described below. For future services using a tunnel, configure explicit hostname routes with verified origin TLS.
- Proxied CNAMEs point to the PROD tunnel for `autotramita.es`, `www`, `partners`, `clientes`, `admin`, `api`, `auth`, `webhooks` and `docs`; `dev.autotramita.es` still points to the unused DEV tunnel. The user chose direct DNS-only access for nested DEV names: `*.dev.autotramita.es` points to the server's IPv4 address and bypasses the Cloudflare proxy and tunnel. The old `*-dev.autotramita.es` placeholder DNS records were removed. Apart from the temporary homepage, these names do not imply running services. CDN, status, webmail and mail records await their respective targets and configuration.
- A temporary Spanish-language development page is live at `https://autotramita.es`, served by the `autotramita-maintenance` nginx container from `maintenance/`, defined in `docker-compose.maintenance.yml` and connected to shared Traefik. `www.autotramita.es` redirects to the apex. The two HTTPS routes and redirect were verified. Manage this separate Compose project with `docker compose -p autotramita-maintenance -f docker-compose.maintenance.yml up -d`.
- Shared Traefik loads `/opt/stacks/traefik/dynamic/autotramita-dev.yml`, a low-priority fallback router that requests a Let's Encrypt DNS-01 certificate for `dev.autotramita.es` and `*.dev.autotramita.es`. The certificate was issued and verified; it expires 2027-02-22 and Traefik manages renewal. The fallback currently returns HTTP 418 until a higher-priority application router is available. This certificate does not change the existing proxied DNS record for `dev.autotramita.es` itself.
- The user subsequently configured `cloud.autotramita.es` as a proxied A record to the shared server and added a router and trusted domain to the existing Nextcloud stack. This hostname currently reaches Traefik directly through the Cloudflare proxy, not through the PROD tunnel; HTTPS login and `/status.php` returned 200, and WebDAV returned the expected unauthenticated 401. At the user's request the unnecessary `cloud-dev.autotramita.es` DNS record was removed. Both application environments use the shared `https://cloud.autotramita.es` address, with separate accounts and folders still to be provisioned. The existing Nextcloud CLI URL remains `https://cloud.finestar.hr`.
- The DNS-scoped token could not read the zone's HTTPS/security settings, so Full (strict) and other Cloudflare security settings have not been verified.
- Next: configure secrets, provision the intended application and Keycloak databases and Nextcloud service accounts, and implement a first application service. When deploying it, add its explicit Traefik router; PROD services planned behind the tunnel also need a verified-TLS ingress rule. Configure application authentication and authorization before exposing private services. Coordinate DNSSEC with the registrar and configure mail separately after verifying the existing mail server.

## Access decision and investigation — 2026-11-24

The user decided Cloudflare Zero Trust / Access is not needed for this single-developer project. Do not configure it as a prerequisite for DEV or admin. Authentication and authorization for private application functions remain application responsibilities.

- The currently available Cloudflare DNS and global tokens could not read the Zero Trust organization (`403`), and an attempt to create a deny-by-default admin Access application returned `403 auth.forbidden`. Listing Access apps, identity providers and policies returned no results with the DNS token; this is not sufficient to establish whether the account is fully provisioned. No Access application or policy was created.
- Follow-up inventory of `/opt/stacks/traefik/secrets/cloudflare/` found that all six `*.api-token` files currently contain the same active token, including the files named `cloudflare_global_allzones.api-token` and `cloudflare_token_admin_create_tokens.api-token`. Thus the names do not establish distinct privileges; the same credential was tested against both account- and zone-scoped Zero Trust organization endpoints and received `403` on both, and the permission-group listing also returned `403`. The all-zones credential is functional for DNS and tunnel creation, as demonstrated above, but these results do not establish Zero Trust administration access. Do not overwrite or rotate the shared token without assessing dependent stacks.
- The shared Traefik also listens directly on public ports 80 and 443. When services are deployed, account for direct origin access and enforce authentication and authorization at the application; DNS records themselves provide no access control.
- The repository currently contains application skeleton directories but no runnable application service. No placeholder application or unverified production router was deployed.

## Nextcloud (revised decision 06, option B)
The existing shared Docker Nextcloud instance is the central document storage; no new Nextcloud, database, Redis, MinIO or storage/storage-dev hostnames. PROD and DEV use separate service accounts, credentials and folder roots in that shared instance. This supersedes the earlier separate-instance decision; the existing Nextcloud is a shared trust and failure boundary. WebDAV + OCS API via service accounts; no direct filesystem writes. Partners and clients access files exclusively via AutoTramita API with business authorization. Authorized internal staff may access Nextcloud via Keycloak SSO when configured; direct access must not bypass document permissions or controlled versioning. No public shares by default. Private documents never cached on CDN.
PostgreSQL holds document metadata, UUID, tenant/client/vehicle/case relationships, type, filename, storage reference, MIME, size, SHA-256, version, uploader, timestamps, scan status and retention. Validate actual MIME and size, quarantine and scan via ClamAV before release; preserve original and business versions. Proposed limits from accepted storage discussion: documents 50 MB, photos 20 MB, video 250 MB, subject to transfer constraints. Authorized short-lived application download links, not assumed native S3 presigned URLs. TLS and encrypted storage, audit, EU data location, GDPR/LOPDGDD. Consistent encrypted offsite backup of files, database and configuration; provider not decided.
Proposed separate roots are `AutoTramita/PROD` and `AutoTramita/DEV`. Under each root: `Tenants/{tenant_uuid}/{Clients,Vehicles,Cases,Contracts,Invoices}`, `DirectClients/{client_uuid}/{Vehicles,Cases,Documents}`, `Internal/{Administration,Accounting,Legal,Templates}` and `System/{Generated,Quarantine,Archive}`. UUID paths rather than personal identifiers. Folder layout does not grant permissions; roots and accounts are not yet provisioned.

## Mail (decision 07, option B)
Existing FS-Mailserver (Postfix/Dovecot) for business mail; external transactional SMTP provider for automatic notifications, provider pending. Mail remains independent of AutoTramita deployment.
Domains: mail.autotramita.es (SMTP/IMAP), webmail.autotramita.es, notify.autotramita.es (transactional sender), bounce.autotramita.es (bounce handling, provider-specific).
Business addresses at @autotramita.es: info, comercial, socios, clientes, soporte, tramites, documentacion, facturacion, contabilidad, pagos, legal, privacidad, seguridad. Use aliases/shared mailboxes as appropriate. Transactional senders: notificaciones@notify.autotramita.es and no-reply@notify.autotramita.es.
DNS plan: mail A/AAAA DNS-only if applicable; apex MX, SPF TXT, DKIM selector TXT/CNAME, _dmarc TXT; notify SPF, DKIM and DMARC; bounce MX or provider-specific records; webmail proxied CNAME; MTA-STS (_mta-sts TXT and mta-sts HTTPS host) and TLS reporting (_smtp._tls TXT). PTR set by IP provider. Actual values and selectors pending existing server/provider verification; avoid duplicate SPF records. SMTP/IMAP must not use ordinary Cloudflare HTTP proxy.
Notification service: queue, retries, audit, Spanish templates for registration, invitations, cases, missing documents, status changes, invoices, payments, reminders, signatures, security and Keycloak password resets. Sensitive documents via authenticated app links, not automatic attachments.
Inbound documentacion mailbox: Dovecot source of truth, Sieve signals, IMAP IDLE and periodic reconciliation, subject to FS-Mailserver integration contract. Scan attachments, store in Nextcloud, associate with verified case; ambiguous matches go to manual review, never match solely by sender address. DEV is configured to use Mailpit and test credentials; outbound-mail blocking is not yet enforced.
