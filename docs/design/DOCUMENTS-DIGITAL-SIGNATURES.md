## 1. Navigation and layout
Proposed /empresa/documentos, /documentos/[id], /documentos/revision, /documentos/firmas, /documentos/plantillas (authorized central editors), /documentos/verificacion under /empresa. Case Documents tab and CRM authorized projections use same components. Desktop 256/72 sidebar, 64 topbar, 24 padding; 12-column grid, Inter, Lucide, navy/blue existing tokens, light/dark/system. Register table, split viewer (page thumbnails, canvas, metadata/review panel); mobile cards, full-screen viewer and camera capture, bottom actions, keyboard alternatives, WCAG 2.2 AA target, 320px and 200% zoom, reduced motion.
## 2. Register and queues
Columns opaque reference, sanitized filename, category, case, branch, version, source, uploader, received date, processing state, review state, signature state, official verification state, expiry, actions. Filters case/service/category/branch/date/source/assignee/expiry and independent states; authorized counts, stable pagination 25/50/100 proposed. Search metadata and permitted OCR fields only; no raw IDs in URLs/logs/saved filters; no cross-tenant autocomplete. Queues Pendientes de revisar, Requieren corrección, Firmas pendientes, Verificación oficial, quarantine restricted to security operators. Empty/no match/loading/error/denied/stale distinct. Bulk download/export separate permission, per-object authorization, manifest and audit, no bulk signing or validation.
## 3. Upload and camera
Select authorized case and requirement (or unclassified inbox scoped to case), drag/drop or picker, mobile camera permission just-in-time; deny fallback file picker. Multi-page capture with edge detection, crop, rotate, glare/blur warnings, retake, reorder/delete before submission, manual accessible alternative. No automatic gallery save, location metadata removed from capture derivative; preserve received original where evidence requires, distinguish derivative from original. Proposed PDF/JPEG/PNG/HEIC allowlist subject to AT-09 limits and conversion support; no executable/archive default. Display size/page limits from server, per-file progress, cancel/retry, resumable upload proposal, idempotent finalization and orphan cleanup. Guest uploads only opaque scoped intake token, rate limits, quarantine, no account claim. No offline sensitive persistence by default; interrupted capture warns before exit. Server validates actual MIME/magic, size, page/pixel/decompression limits, malware and malformed/encrypted files; reject or isolate, no preview/OCR before safe clearance. Private S3, metadata PostgreSQL RLS, opaque keys, short-lived scoped transfer, checksum integrity; finalize only after object verification. No public URLs.
## 4. Independent states
Ingestion: pending/uploading/received/quarantined/cleared/failed/rejected. OCR: not requested/queued/processing/completed/partial/failed. Classification: unknown/suggested/confirmed/corrected. Review: pending/needs correction/validated/rejected/expired/superseded. Signature: not required/draft/requested/partially signed/completed/declined/expired/canceled/validation failed. Official verification: not checked/pending/matched/mismatch/unavailable/manual review/revoked if issuer confirms. Illustrative labels, not canonical enums. Received, OCR complete, signed and official verification never imply each other. Service-version checklist controls mandatory/conditional documents, accepted versions and transitions; received count distinct from validated count.
## 5. OCR and classification
After clearance, tenant-scoped asynchronous jobs, retry/backoff and failure manual fallback. Suggested types DNI/NIE/passport, permiso de circulación, ficha técnica/ITV, invoice/contract, mandate, COC, Ficha Reducida, tax/fee receipt, official resolution, other. Show confidence per field and category, page/bounding region, original value, normalized suggestion, source/version, reviewer and correction. Spanish and foreign documents, handwriting/low-quality flag; no guessed missing fields. Compare VIN, plate, identifiers, dates and names to authorized CRM/case snapshot; conflicts side-by-side, no automatic overwrite, explicit accept selected fields and optimistic version check. No automatic identity, ownership, signature or authenticity validation from OCR. Treat embedded text as untrusted data, never instructions. Provider selection, residency, DPA, no training/reuse, retention and confidence thresholds open; minimize transmitted data.
## 6. PDF viewer
Safe sandboxed renderer, page navigation, thumbnails, zoom/fit/rotate, search authorized text layer, keyboard, accessible text alternative, mobile full screen. Disable active PDF scripts, embedded launches and external fetch; links require explicit safe handling. Show original vs sanitized preview, signed original preserved byte-for-byte, annotations separate overlays, no mutation. Metadata panel category, case, source, version, checksum, uploader, review, signature, official verification. Side-by-side comparison, page highlights, request correction with reason and recipient, validate/reject only authorized reviewer. Download original/approved derivative separately, short-lived authorization, audit; watermark only derivative, never signed original. No promise screenshots can be prevented.
## 7. Versioning and reuse
Immutable original bytes and hash per version; logical document reference, version number, parent, source, author, reason, timestamp, review and signature bound to exact hash. New upload creates new version; signed/submitted version locked, historical case snapshots pinned; superseding does not revoke legal evidence. Restore creates new version, not destructive overwrite. Concurrent updates conflict; duplicate checksum only within authorized scope, no cross-tenant existence oracle. Reuse reference only after target case entitlement/purpose check; standalone CRM documents remain gated by AT-09 entitlement decision. Archive separate from retention/deletion, legal hold blocks purge; privacy requests AT-20.
## 8. Templates and generated forms
Central versioned template registry by service/version, authority, language, effective dates, source/license, required fields, signature requirements, approved reviewer. Draft -> review -> published -> retired; no silent changes to in-flight cases. Generate from case snapshot, show field mapping and missing/conflicting data, preview, explicit approval, output immutable PDF with template version and source snapshot/hash. Distinguish internal draft from official form; no fabricated agency logo/CSV/stamp. PDF/A only where required and compatible with signature; no conversion after signing. Templates include applications, sale contracts, mandates, checklists, cover letters, receipts only when legally approved. External official forms verified by AT-15/20. No automatic submission.
## 9. Mandates
Principal, representative, scope/service/case, authority, validity, evidence, signature requirement, reviewer, status draft/pending/active/expired/revoked/rejected. Show individual corporate signatory and authority evidence; special cases manual review. Signed mandate not automatically verified representation or portal grant. Revocation blocks future acts and notifies AT-07; preserve lawful historical acts. Regulated actions only authorized gestoría; engineer receives minimum assigned case data for Ficha Reducida, not full CRM.
## 10. Electronic signatures
Proposed provider-neutral flow: choose exact document version and signers/roles/order, validate authority and required signature level per procedure, preview complete content and consent, explicit send request, authenticate signer via approved provider, track per signer, decline/expire/cancel/resend (invalidate old invitation), verify callback and retrieve signed original + evidence. Simple/advanced/qualified eIDAS levels distinct; drawn signature or OTP alone not automatically advanced/qualified; qualified signature requirements and accepted formats per authority subject to AT-20/15 review. PAdES candidate for PDF, other formats only if required; provider/QTSP, certificate validation, trusted timestamps, long-term validation and evidence retention open. Never collect private signing keys or certificate passwords. Verify cryptographic integrity, certificate chain/trust, revocation/time evidence, signer identity and exact document hash; unknown/unavailable distinct from invalid. Authenticated signed webhooks, replay/idempotency, reconcile provider status, reject mismatched version/signers, no success from redirect alone. Evidence package: signed bytes, hash, consent, signer/role, provider reference, timestamps, validation report and audit; minimized access. Partial signature not complete; modified document requires new request; canceled request cannot erase completed signatures. No signing on behalf without legal authority.
## 11. CSV official verification
CSV = Código Seguro de Verificación, not comma-separated file. Capture issuer and code manually or OCR suggestion; show source page and confirm. Use centrally approved issuer-specific official verification endpoint or explicit external official portal link; no arbitrary URL fetching, SSRF protection, no code in analytics/logs/referrers. No assumption DGT/AEAT/ITV API access or universal CSV format. Compare returned official document/metadata with submitted original (hash where identical bytes, otherwise reviewed material fields), record issuer, timestamp, method, result and evidence. Code exists alone not proof of match; no response/unavailable distinct from invalid, mismatch manual review, revoked only issuer evidence. Manual verification fallback with authorized reviewer and evidence; no bypass CAPTCHA or access controls. Signature validation independent. Official links and legal acceptance validated in AT-15/20 before release.
## 12. Security and roles
OWNER/ADMIN authorized branch scope; MANAGER/EMPLOYEE assigned scope and explicit upload/review permissions; VIEWER read-only if document entitlement, sensitive download/export separately granted. Customer only case grants and allowed documents, partner only assigned minimum, central support scoped audited access. Template publication and security quarantine separate privileged roles; proposed separation of uploader/reviewer for high-risk documents. RLS forced, composite tenant FK, server context on every request/job, reauthorize previews/downloads/search/counts/exports, short TTL, revocation blocks new access; existing signed URLs limited by TTL or proxy where immediate revocation required. Encryption transit/at rest, key management open, private cache no-store, no raw PII/CSV/tokens in logs, audit actor/tenant/branch/object/version/action/reason/outcome/time, immutable security audit separate business timeline. Retention per category/legal basis, holds, backups/purge lifecycle, incident response and provider contracts AT-20. No real PII in demos.
