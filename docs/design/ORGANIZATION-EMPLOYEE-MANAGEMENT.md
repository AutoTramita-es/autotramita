## Company profile and verification (D01–06,17)
Datos de empresa: legal name, entity type COMPANY/SELF_EMPLOYED, legal form, NIF, registered/billing addresses, contacts, representative evidence, verification status, last review, next annual confirmation, linked primary branch; credit summary read-only only with permission, separate financial model. OWNER application role is not legal ownership. Self registration or central manual creation both require manual approval. Candidate OWNER can supplement application, no production privileges. Company evidence NIF, registration, representative authority and identity; autónomo NIF/NIE, identity and tax/business registration. Checklist with uploaded/review/pending/rejected evidence, secure private access, reason and reviewer/time where authorized. Automated format/duplicate/available lawful source checks advisory; unavailable or inconsistent results manual review, never imply official API access. Tenant lifecycle DRAFT/PENDING_VERIFICATION/ACTIVE/SUSPENDED/CLOSED; separate review PENDING/MORE_INFO_REQUIRED/APPROVED/REJECTED; rejected can resubmit new review preserving history, abuse blocks central. Duplicate NIF: generic response, controlled access request via existing OWNER/ADMIN or central verified recovery, no staff disclosure. Contacts editable OWNER/ADMIN; legal name and registered address change request with evidence/review, NIF locked, different legal entity new Tenant and separate case/obligation handling. Annual confirmation at least, risk/change-driven checks, warnings and targeted restrictions not automatic full suspension. Verification documents minimized, retention pending AT-20.

## Branches (D07–09,22–23)
Centros list code, name, city/address, primary, lifecycle, authorized employee/open case counts, intake restriction; detail Datos/Equipo/Expedientes/Historial. BR-0001 prepared at onboarding with proposed registered address, applicant confirms physical location; active primary only after address validation and tenant approval. OWNER/ADMIN create additional DRAFT with name, system immutable nonreusable tenant sequence; complete street/number, postal code, city, province, country before activation/reactivation; contact optional. Validate ownership/address/duplicates, suspicious manual review. DRAFT->ACTIVE->INACTIVE->ACTIVE only, no hard delete or return to draft. Exactly one active primary per active tenant; atomic primary switch. Branch is not legal entity or credit account. OWNER/ADMIN implicit all current/future branches, other roles explicit active assignments. Close wizard: block new intake via separate closing restriction (not invented lifecycle enum), preview unfinished cases and assignments, choose eligible same-tenant active destination or formal completion per D22, replace primary first, retire assignments preserving history, atomic final validation against concurrent intake. Completed cases retain history; no unfinished orphan. Reactivation validates address and authority, no automatic staff/case restoration. Case transfer wizard source/destination/reason/assignee, check status/permissions both branches, retain case ID, tenant, documents, financial identity, original branch history; OWNER/ADMIN all active branches, MANAGER explicit transfer permission and both assigned, EMPLOYEE request only with authorized approval, VIEWER none. Bulk preview per-case eligibility and result, no silent partial success.

## Team and invitations (D09–12,24–25)
Equipo register name, verified contact as authorized, role, membership status, assigned branches, last activity if lawful/authorized, unfinished count; filters role/status/branch and search; detail Perfil/Centros/Permisos/Finanzas/Actividad. Global User separate from TenantMembership; one user can hold independent roles in multiple tenants. INVITED/ACTIVE/SUSPENDED/REVOKED. Invite wizard email, role, branch assignments, permitted grants, review and send; OWNER/ADMIN invite MANAGER/EMPLOYEE/VIEWER, OWNER alone ADMIN; MANAGER with explicit permission only EMPLOYEE/VIEWER in own branches, cannot grant higher roles or delegate beyond authority. OWNER transfer separate. Token single use, 168 hours from issuance, verified email match, authenticated acceptance with company/role/branches preview; mismatch denies without consuming, registration does not extend expiry. Recheck inviter authority, tenant/branch status and grants atomically; ordinary valid acceptance activates without second approval. Resend invalidates prior token and starts fresh 168h; revoke/expired/superseded cannot accept; no token in audit. Delivery status distinct from acceptance. No global account enumeration. Revoked employee returns via new invitation and fresh grants, suspended member reactivation validates current grants and branches; never restore invalid grants. Role/branch changes immediate across sessions; no self elevation; OWNER alone adds/removes/suspends ADMIN; preserve last active OWNER, concurrency-safe. OWNER/ADMIN branch changes; manager delegation invitation only unless further approved. VIEWER read-only.

Role baseline plus individually granted operational capabilities; matrix grouped Expedientes, Clientes/Vehículos, Documentos, Equipo, Finanzas, Exportación, Auditoría. Show inherited/explicit/not permitted, scope and reason; effective permission = current membership + tenant/branch status + role/grant + resource/action constraints; never bypass reserved authority. Proposed granular controls case create/edit/assign/transfer/request, upload/review, quote, discount, deferred, finance view/margin/pay/refund request, export categories; canonical identifiers pending. No blanket manager administration. OWNER/ADMIN set employee discount and deferred permissions independently, internal limits per employee; proposed EUR/percent discount cap and per-operation deferred cap, exact units/period/approval policy pending AT-12/13. Show effective cap and company credit status separately, never employee credit account. Validate caps and actual available tenant credit atomically on financial action; no public price edits or central credit limit/terms changes. Dealer-funded discount, AutoTramita agreed amount unchanged. Finance/personal/bulk export separate permissions; OWNER/ADMIN allowed tenant categories, MANAGER authorized own branches, EMPLOYEE limited permitted own records, VIEWER read-only exports only if explicitly authorized under final matrix. Scoped expiring export links, audit, no unauthorized counts. No self-grant or escalation via UI/API.
## Deactivation and reassignment (D12)
Suspend or revoke dialog previews affected membership, authorized unfinished cases, branch scope and consequence; explicit confirmation and reason, never require reassignment before revocation. Immediately deny affected tenant across sessions, clear protected state and invalidate relevant context; global account and other memberships unaffected. Preserve case tenant/branch/documents/status/authorship. Flag unfinished cases, route responsibility to authorized branch MANAGER or ADMIN/OWNER or reassignment queue; responsibility is not automatic mutation of case assignee. Queue shows case/service/branch/former assignee/deadline/elapsed time/urgency; authorized target active membership with destination branch access; single/bulk review and audit. In-app/email notify active OWNER/ADMIN and eligible affected MANAGER; minimal email, safe links, reauthorize. Daily aggregated reminders max one per recipient/tenant/day, stop when resolved; 72 elapsed hours per outstanding episode -> URGENT_REASSIGNMENT, notify active OWNER/ADMIN once per episode, daily reminders continue; valid assignment clears marker. Delivery failures independent of access revocation and queue state. No auto branch transfer. Existing statutory deadlines unaffected.
## Ownership and tenant lifecycle (D13–16)
Transfer OWNER wizard existing OWNER initiates, new verified user accepts and confirms identity, central verifies legal authority and approves; old grants unchanged until approval except security restriction; multiple owners permitted ADR-009, last active owner protected, exact post-transfer grants explicitly reviewed; recovery when old owner unavailable separately controlled with evidence and audit. No ordinary invitation bypass. Tenant suspension central: block new cases and credit, limited OWNER/ADMIN docs/invoices/communication unless risk requires full block; central evaluates existing cases individually for authorized completion, stop or transfer. Credit-only suspension ADR-007 distinct, prepaid remains. Closure OWNER request, review open cases, invoices, liabilities and disputes, stop intake, resolve cases before CLOSED, lawful archive and delete/anonymize remainder, historical NIF duplicate linkage only lawful basis. Reactivation same legal entity retains tenant/history, verify NIF/status/representative/OWNER/obligations again; no automatic former staff or credit restoration. Central decisions and reasons audited.
## Security, sessions and support (D18–20,24)
Seguridad global account: verified email, password change/recovery, optional 2FA for ALL dealership roles including OWNER/ADMIN, enable/disable/recovery UX subject AT-02; no mandatory MFA introduced. Rate limiting and security events; no passwords/OTP in logs. Sesiones activas device/browser, approximate location labeled estimate, last activity, current session, individual revoke or sign out others; password change may revoke others per approved policy. Session-specific active tenant/branch, preferences only initialize new sessions; validate every request, switch without login, no stale context, clear on revocation. Single active branch for operations; aggregate read only if separately authorized, not a branch context. No eligible branch -> safe landing. Support default technical diagnostics only; OWNER/ADMIN grant purpose/scope/time-limited business access with explicit review and revoke, show expiry/history; exceptional access separately privileged with reason/audit/post-review. No invisible impersonation or password sharing, no uncontrolled RLS bypass. Global account sessions visible only to account holder, tenant admins see only authorized tenant access information.
## Audit (D21,27)
Registro de auditoría filters date, category, actor, branch, target, outcome; event detail timestamp/timezone, actor and affected membership, tenant/branch, action, reason, relevant redacted before/after, correlation reference. Significant verification, role/branch/invite/owner, access, case transfer, docs, discount/payment/export/support/security events; append-only protected from alteration, no raw tokens/passwords/full identity documents or unnecessary clicks. Audit is not employee surveillance or unrestricted global account history.
