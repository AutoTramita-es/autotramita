# F2 — Registar odluka (identitet, autentifikacija, sigurnost)

Datum: 2026-11-24 | Status dokumenta: **D01–D41 i D43 ACCEPTED (owner, 2026-11-24, F2-CP00); D42 OPEN (AT-20)** | Bez implementacije izvan odobrenog paketa
Povezano: [AT-02 specifikacija](../specifications/AT-02-identity-security.md) · [Plan](F2-IMPLEMENTATION-PLAN.md) · [Execution order](F2-EXECUTION-ORDER.md) · [Kriteriji prihvaćanja](F2-ACCEPTANCE-CRITERIA.md)

**2026-11-24 — F2-T09-REC:** Owner confirmed D37 requires verification before changing the existing login and confirmed token minimization and optional first/last names, and approved the limited durable D37 recovery and notification mechanism. Implementation and verification: [CP09 reconciliation](F2-CP09-RECONCILIATION-REPORT.md) (D37 implemented, disabled in production by O15). CP09 is not accepted; D42 remains OPEN. This note supersedes conflicting older D37 and proposal-status wording below, not the remaining accepted decisions.

**Owner decisions on F2-T09-REC findings (2026-11-24, verbatim: „Autoriziram F-0 opciju (a) i F-1 opciju (b).”), ACCEPTED:** F-0 (a) periodička provjera neriješenih promjena lozinke na 60 s workeru (dopuna D20) · F-1 (b) registracija passkeya isključena dok WebAuthn ne bude podržan u LoA2 toku (privremeno sužava D22 na TOTP; F-1 (a) nije odlučen).

**Owner decisions of 2026-11-25 (F2-T09-REC completion order), ACCEPTED** (verbatim extracts in the [execution order](F2-EXECUTION-ORDER.md)):
- **F-1R (d)** — TOTP, recovery codes and WebAuthn are part of the level-two flow (extends D22/D23/D41). Passkey registration stays off until separately approved (F-1 b unchanged).
- **F-2** — a step-up lasts at most 10 minutes from the successful authentication with the factor; neither single sign-on nor a new token extends it; the 5-minute limit stays where defined (amends D23).
- **F-3** — sensitive account actions need a fresh password for people without MFA and a fresh authentication with the existing factor for people with MFA; recovery stays a separate flow (amends D23 and AT-02 §7.2).
- **F-4** — a minimal safe resolution for D37 `MANUAL_REVIEW`; privileged interface may depend on T10/T11 (completes D37).

**Superseded 2026-11-25:** the open decision on F-1R-B and F-3K was taken (option A, below).

**Owner decision of 2026-11-25 (F2-T09-REC — Final MFA Security Decision), ACCEPTED** (record in the [execution order](F2-EXECUTION-ORDER.md)): option **A** of the CP09 report with its supplements. Amendments, effective with this decision:
- **D22/D23:** LoA1 is “password” only for people who never set up a second factor; whoever has one proves it at every password sign-in (web, mobile, account console). One proof is enough for LoA2. A credential change at the provider (password, factor set-up) always starts with a fresh sign-in; no credential is removed at the provider, removal goes through the application.
- **D41:** recovery codes stay, as a backup of a permanent factor (one-time code or WebAuthn): generated only after a fresh proof of one, never an account's only factor; the last permanent factor cannot be removed while codes remain; spending the last code needs the permanent factor and ends the person's other sessions. Accounts holding codes only (from before) must be marked `at_mfa_required` by an operator; unmarked they are refused. A marked account without any usable factor stays locked until a controlled recovery (T10 authority, T11 interface).
- **New state:** user attribute `at_mfa_required` (realm user profile, administrators only): an account that must never fall back to the password alone. Set by an operator; automatic setting is not decided (it would conflict with I07).
- F-1R-B stays P1 while takeover is possible (it is closed by the above). A new architectural component needs its own justification and authorization.
- **Closed 2026-11-25:** F-1R-C (P1) and residual F-3K, by the Keycloak security provider (D44; [CP09 report §2](F2-CP09-RECONCILIATION-REPORT.md#2-keycloak-security-provider)).

**Owner decision of 2026-11-25 (Keycloak Security Provider authorization), ACCEPTED** (record in the [execution order](F2-EXECUTION-ORDER.md)): a minimal own Keycloak provider in Java using Keycloak SPIs, a reproducible own Keycloak image (upstream pinned by digest), integrated in local CI and GitHub Actions; amends ADR-008 and D43. Amends I07, D22, D23 and D41: `at_mfa_required` is a permanent obligation, set automatically with the first permanent factor; recovery codes never authorize a new permanent factor or new codes; an obliged account without factors stays closed (recovery T10/T11); voluntary switch-off only through a controlled process (fresh password and permanent factor, explicit confirmation, codes revoked, sessions ended, audit), never for people whose MFA is mandatory (platform grants, T10). Not approved: a Keycloak fork, a new external service, a new persistent database, new public ports.

**D44 (ACCEPTED 2026-11-25, owner, Keycloak Security Provider Authorization):** a minimal own Keycloak provider (`identity/keycloak/provider`, Java, Keycloak SPIs only, no third-party dependency) decides credential changes at submit time under a database row lock (`AT_MFA_GUARD`, Keycloak's database), manages `at_mfa_required`, offers the controlled switch-off `at-disable-mfa` and makes the realm unusable without it (`at-security-guard`). Reproducible own image from pinned images, built in local CI and GitHub Actions; not pushed to a registry. Not approved: a fork of Keycloak, a new external service, a new persistent database, new public ports. Design, guarantees and limits: [provider README](../../identity/keycloak/provider/README.md).

Predložena minimizacija tokena (ukloniti `profile`/`roles` scope) i postupanje s imenom/prezimenom iz izvještaja **nisu izričito prihvaćeni** i ostaju PROPOSED prijedlozi za T09; T02 validator ne ovisi o njima (ignorira sve osim potrebnih claimova). Autoriziran je isključivo **F2-T02**.

## Pravila registra
- **ACCEPTED (naslijeđeno)** = već prihvaćeno u ADR-u, G6, AT-01 §10a ili potvrđeno u AT-03; F2 ih samo primjenjuje i **ne otvara ponovno**.
- **PROPOSED** = prijedlog F2 analize. Ne vrijedi kao odluka i ne smije se implementirati dok vlasnik izričito ne prihvati (ADR-008). Za svaku je navedena preporuka, obrazloženje i alternative.
- Izvor „F2 analiza" znači: zaključak izveden iz navedenih prihvaćenih dokumenata i pregleda koda na `dev`, ne novi poslovni zahtjev.
- Odluke koje mijenjaju prihvaćenu F1 arhitekturu označene su **[F1-AMANDMAN]** i zahtijevaju posebno odobrenje (D17).
- Vlasnik može prihvatiti sve preporuke jednim paketom (§4); nijedna odluka se ne smatra prihvaćenom bez toga.
