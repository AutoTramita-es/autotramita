# Public service pages — UX specification v1.0
Date: 2026-11-24. Status: proposed for product-owner review; no implementation.
Parent: [Homepage](WEBSITE-STRUCTURE.md), [Brand](BRAND-IDENTITY.md), [Icons](ICON-SYSTEM.md), AT-18. Dependencies AT-02/04/05/06/07/09/10/11/12/13/14/15/20. ADR-002/003/004/005/006/007/008/009 authoritative.

## Routes and catalog
Proposed /servicios (search/filter published services), /servicios/[slug] (one reusable server-rendered template), /tramites/nuevo (service selection or preselection). Slug is public, not an authorization token. Backend is source of truth for published version, locale, eligibility, pricing, required fields/documents and workflow. Marketing metadata editable through governed publication; never allow arbitrary HTML/scripts. Exact API schemas remain AT-06/AT-12 under ADR-004. Public cache contains only public catalog projection; invalidate on publication or withdrawal; personalized quotes and cases never shared-cache. Draft/unpublished entries excluded from navigation and sitemap; withdrawn service cannot start new case, existing cases retain pinned version. Unknown slug 404; retired URL redirect only to genuine replacement.

## Layout and copy
Desktop 1280 max width, 12-column grid, main 8 / sidebar 4, 24px gap, Inter, brand tokens. Header and footer reuse homepage. Breadcrumb Inicio > Servicios > service title. Hero H1, short description, 4:3 illustration, availability and applicable conditions. Main sections: “¿En qué consiste?”, “¿Quién puede solicitarlo?”, “Documentación necesaria”, “Cómo funciona”, “Qué incluye el servicio”, “Preguntas frecuentes”, “Servicios relacionados”. Sidebar price card sticky only when it fits viewport and does not obscure focus/footer. Mobile stack hero, price summary, requirements, workflow, FAQ; optional bottom CTA with safe-area and no obscured content. Primary “Iniciar trámite”; secondary “Consultar requisitos” / “Contactar”. If eligibility uncertain use “Comprobar requisitos”. No invented SLA or government affiliation. Public copy Spanish es-ES, accessible headings and links.

## Dynamic pricing
Public retail price centrally controlled; same service/version and pricing conditions across dealerships. Display service amount, IVA treatment and consumer-facing tax-inclusive service subtotal when determinable, separate statutory fees and taxes, total payable now and amounts payable later/to third parties only if known and approved. No double counting; label unknown amounts “Pendiente de cálculo” not zero. Distinguish exact total, estimate, and unavailable quote. “Desde” only for a genuine applicable minimum with conditions. If no verified price, “Consultar precio”; do not accept payment until authoritative quote and required disclosures. Show quote expiry and assumptions when supplied. Server recalculates at confirmation, rejects stale/expired quote and presents changed breakdown for explicit reconfirmation. Currency EUR es-ES; backend decimal arithmetic and rounding; frontend does not compute authoritative tax. Public price never personalized by dealership; authorized dealership-funded discount appears only in scoped quote with public base, discount, customer total; AutoTramita agreed amount unchanged. Credit only in authorized B2B flow subject to server approval/available limit, not public promise. Pending payment never shown settled. Provider, funds flow, tax treatment and allocation pending AT-12/14 approval. No live example amounts in design.

## Documents and eligibility
Render versioned requirements grouped “Obligatorios”, “Según tu situación”, “Opcionales”. Each shows label, purpose, accepted format/limits if configured, applicability and how to obtain. Conditional rules evaluated server-side from answers; unknown conditions shown as conditional, not waived. Public page never requests upload or identity number; upload only inside authorized request context with private storage, scan/quarantine, validation, retry and access controls per ADR-005. No sensitive data in analytics, URL, browser persistent storage or public cache. Required document examples below are illustrative, not official legal checklists. AT-06/15/20 must verify jurisdiction, current rules and professional authority before publication.

## Start request — proposed UX
1. Service selected: show version/current availability; allow guest or sign-in, no mandatory account.
2. Eligibility questions and vehicle/party details dynamically driven by service definition; collect minimum necessary, show why needed. Server resolves tenant context (direct public intake ownership policy remains open); never trust tenant IDs from browser.
3. Contact and identity/representation information as required; secure verification according to AT-02/04; no automatic case claim by matching email.
4. Documents: upload with per-file progress, accessible errors, scan pending and missing-document indicators. Allow later completion only if workflow permits.
5. Review: service/version, answers, documents, authoritative quote and terms/privacy notices. Separate required acknowledgments from optional marketing consent. Signature/payment when required by actual workflow, not fixed mandatory sequence. Clear payment obligation before binding order.
6. Submit idempotently; prevent duplicate cases/payment attempts. Server validates eligibility, price, documents and authorization. Show receipt/reference and actual state; pending verification/payment not completed. Offer secure account linking with short-lived single-use proof per ADR-003. Guest resume requires scoped secure capability/verification, never guessable case reference; exact mechanism pending AT-02/04/07. Back/refresh/retry preserve authorized draft where supported; no sensitive localStorage.
This is UX sequence, not a new case state machine. Actual case creation boundary, draft retention, signature/payment order and incomplete submission policy remain domain decisions. Existing cases retain service definition/version; later publication must not silently change requirements.

## UI states and accessibility
Catalog loading skeleton with accessible status; failure retry/contact; empty list; unavailable/withdrawn service; price pending/estimated/exact/expired; ineligible with explanation and permitted alternatives; document conditional/required/uploading/scanning/rejected/accepted; submission pending/success/error with safe retry. Do not show internal exception, tenant data or raw provider messages. Keyboard navigation, focus management, error summary and field associations, semantic lists, WCAG 2.2 AA, reduced motion, 320px no overflow. Price card uses text labels, not color alone. SEO unique title/description/canonical for published pages; noindex request/quote/account pages; structured data only verified service/offer data; no fabricated ratings. Use responsive images and lazy loading below fold.

## Acceptance criteria
AC01 same template supports multiple published services without code changes; AC02 draft/withdrawn service cannot start new request; AC03 public prices consistent across dealerships; AC04 statutory charges separate and unknown not zero; AC05 expired/changed quote requires reconfirmation; AC06 discounts scoped and dealership funded; AC07 conditional documents server validated; AC08 guest can submit without registration; AC09 secure claim not email-only; AC10 tenant context server validated; AC11 private upload and no shared caching; AC12 idempotent retry; AC13 payment pending not paid; AC14 Ficha Reducida outsourced by AutoTramita; AC15 physical ITV caveat; AC16 mobile/keyboard/contrast; AC17 catalog error/empty/unavailable states; AC18 existing case version preserved; AC19 no unverified legal requirements or prices published; AC20 no code or deployment authorized.
