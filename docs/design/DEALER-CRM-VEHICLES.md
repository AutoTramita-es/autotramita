# Dealer CRM & Vehicle Registry — AT-18 / 09.4
2026-11-24 | PROPOSED UX for review, no implementation/deployment.
Sources: [Master](../MASTER-BLUEPRINT.md), [AT-04](../specifications/AT-04-customers-vehicle-owners.md) (D01–D25 proposed, not accepted), AT-05 (not yet specified), ADR-002/003/004/005/006/007/008/009, AT-03 decisions, SAAS-APPLICATION-SHELL.md, CASE-MANAGEMENT.md. Vehicle-specific rules below are proposals for AT-05 review, not new accepted ADRs.

## Information architecture
/empresa/clientes, /clientes/nuevo, /clientes/[id], /vehiculos, /vehiculos/nuevo, /vehiculos/[id] under /empresa; duplicate and verification queues permission gated. Shared shell, 24px spacing, 12-column desktop grid, Inter, Lucide, existing light/dark/system tokens. List table on desktop, cards on mobile, 320px and 200% zoom. Header count, search, filters, new action, authorized export. No PII in URL, analytics or saved search. Context switch clears selection and cached results.

## Customer list
Columns reference, display name, person/company, masked identifier, contact (masked according to permission), verification summary, authorized branch, active cases, updated date, actions. Search authorized name/reference/contact/identifier via protected request; exact ID lookup tenant scoped, no global autocomplete. Filters type, status, branch, verification, active cases, representative status, updated range. Stable sort, server pagination 25/50/100 proposed; counts only authorized rows. Empty/no matches/loading/error/stale/denied distinct. Export requires separate personal/bulk permissions, preview scope and audit.
## Customer creation and editing
Type Persona física / Persona jurídica. Minimal name and authorized branch; email optional if service permits; no account required. Person: given names, surnames (second not mandatory), nationality/birth date only if needed. Company: legal name, trade name optional, legal form, registration country; individual signatories separate. Identifiers DNI/NIE/NIF, passport or foreign tax ID with issuer country/type, format check not identity verification. Contact email/phone with purpose and separate verification; international address lines, postal code, locality, province, country, address purpose. No blanket marketing consent; optional marketing separate. Dynamic required fields per service. Duplicate candidate review only within authorized scope; verified exact match reuse/review, approximate matches never auto-merge; inaccessible branch blind request without existence disclosure. Type correction after use controlled, version conflict handling. Save and optionally open case, no automatic account/grant.
## Customer detail
Header display name, reference, type, active/archive status, independent identity/contact/representation verification, branch context; actions Editar, Nuevo expediente, Solicitar verificación, Archivar subject to permission. Tabs Resumen, Contactos y direcciones, Identificación, Vehículos, Representación, Expedientes, Documentos, Historial. Summary cards active cases, linked vehicles, active mandates only authorized counts. Mask ID by default; reveal only explicit permission and audited purpose. Separate roles per case: applicant, buyer, seller, payer, current/future owner, co-owner, holder, representative. No implication payer is owner or entitled. Case list shows role and snapshot version, not all other branches. Editing CRM never rewrites signed documents, submitted forms, invoices or case snapshots. Archive preserves obligations and lawful portal grants; privacy requests/legal holds AT-20.
## Representation and claims
Principal and individual representative, case/service scope, validity, evidence, reviewer, status draft/pending/active/expired/revoked/rejected. Company representatives use personal accounts; no shared company login. Evidence of authority separate from portal grant; revocation immediate, preserve past acts; notify pending case workflow. Minors, estates, leasing, incapacity, corporate signatory exceptions manual specialist review. Claim one case only: verified login + short-lived single-use token + independent entitlement proof, never email/VIN/NIF alone; no automatic grant to all customer cases. Disputes manual, generic errors. AT-04 proposed token parameters remain pending. Merge privileged review, conflicts block, preserve aliases/snapshots, individually re-evaluate grants, no automatic expansion.
## Vehicle list
Columns reference, VIN masked where needed, plate + issuing country, make/model, category, first registration date, recorded holder (only authorized), ownership verification, active cases, updated. Filters make/model, category, registration country/status, ownership evidence status, branch, case status, updated range. Search normalized VIN/plate/reference in authorized scope only. No external registry lookup assumed. Same VIN in different tenants remains isolated; no global vehicle CRM.
## Vehicle create/edit (AT-05 proposal)
1 Identificación: VIN/bastidor, registration plate and country, foreign/temporary/unregistered status. Normalize VIN uppercase and trim; standard modern VIN 17 characters excluding I/O/Q, do not impose universal check digit or reject documented historical/nonstandard chassis identifiers; exception review with evidence. Never fabricate missing VIN/plate; service rules determine whether draft can proceed. Plate not permanent identity, country and validity period required for history. Duplicate exact VIN candidate within tenant, branch visibility guarded; conflicting evidence review, no automatic merge. 2 Datos técnicos: make/model/variant/version, category, first registration date, country, fuel/powertrain, displacement, power kW, masses, emissions, homologation, ITV and odometer reading with date/source only as needed; units explicit, unknown distinct from zero, no guessed data. 3 Titularidad: choose authorized party, role, evidence and effective date if known; pending vs confirmed. 4 Documentos y revisión: source, verification, discrepancy review, save; no claim of DGT registration. OCR suggestions require review; external VIN decoding optional pending provider, legal basis, coverage and authorization. Preserve source and timestamp per verified fact; changes versioned and audit.
## Vehicle detail
Header make/model, reference, masked VIN/plate, registration country, verification status. Tabs Resumen, Datos técnicos, Matrículas, Titularidad, Documentos, Expedientes, Historial. Context panel next permitted action, missing evidence, linked cases. Technical fields grouped identification, powertrain, dimensions/masses, homologation/ITV, emissions; source and date visible. Plate history records country, type, valid from/to, source; corrections preserve previous record. No implied official live status.
## Ownership history
Separate legal ownership, registered holder, keeper, leasing and proposed buyer; allow co-owners, unknown effective dates and disputed evidence. Timeline records party, role, effective period, recorded date, source, verification, linked case and correction history. Pending transfer is not completed ownership; cancellation leaves prior confirmed record unchanged. Only authorized verified evidence and approved AT-05/07 transition may confirm change; do not automatically close prior owner on case creation/payment/OCR. Conflicting or overlapping claims flagged for review; legitimate co-ownership allowed. No inferred ownership from possession, payment, registration plate or customer login. History is tenant-recorded evidence, not certified official registry. Limit former owner data to authorized purpose.
## Documents and cases
Customer/vehicle tabs show only authorized case-linked documents under ADR-005; proposed standalone document entitlement model requires AT-09 approval before enabling independent uploads. Reuse references only after target-case authorization and purpose check, no cross-tenant copying or blanket access from CRM link. Received/validated/rejected/quarantine/expired distinct, version/source, secure short-lived preview/download, audit. Case picker carries explicit party role, vehicle and branch, revalidates service requirements and creates immutable snapshots; linked case table status, role, service, date, branch, next deadline if authorized. No automatic legal/financial effects.
## Roles and security
OWNER/ADMIN all authorized branches; MANAGER/EMPLOYEE assigned branch and permissions; VIEWER read-only masked. AT-04 proposed branch grants, sensitive master-field review and merge permissions pending confirmation. Partner case-specific minimum projection, no CRM browsing. Support scoped approved access per AT-03. RLS, composite tenant references, server authorization for every search/count/action/download/export, no existence oracle, no private shared cache, no raw identifiers in logs. Revocation immediate; audit sensitive reads, changes, merge, representation and export. No real PII in demo. Suspended tenant restrictions per AT-03. Generated clients ADR-004; no new API contracts.
